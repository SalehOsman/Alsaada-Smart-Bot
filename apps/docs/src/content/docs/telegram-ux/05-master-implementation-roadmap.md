# 🗺️ خارطة الطريق التنفيذية للمنظومة الجديدة
## Al-Saada Smart Enterprise Master Implementation Roadmap

> [!IMPORTANT]
> **مبدأ التنفيذ المنضبط (Phase-by-Phase Execution):**
> يتم بناء المنظومة الجديدة في مجلد `F:\Alsaada-Smart-Bot` دون المساس بالمشروع الحالي (`F:\HR`). كل مرحلة تُختبر برمجياً وتُعتمد قبل الانتقال لما يليها، مع استخدام المشروع القديم كمرجع قياسي مطابق للبيانات وقواعد العمل.

---

## 📊 المراحل التنفيذية الست (The 6-Phase Roadmap)


```
┌────────────────────────────────────────────────────────────────────────┐
│  المرحلة 0: إعداد بيئة المشروع النظيف والحزم الأساسية (Project Setup) │
│  المرحلة 1: بناء الحزم التأسيسية (National ID, Regional, UX Helpers)   │
│  المرحلة 2: بناء محرك قراءة الفواتير بالذكاء الاصطناعي (AI Vision)      │
│  المرحلة 3: بناء محرك التوليد الآلي لشيتات جوجل (Auto-Provisioner)     │
│  المرحلة 4: بناء المكونات المشتركة التفاعلية (Core UI Components)      │
│  المرحلة 5: نقل وتفعيل موديولات الأعمال الرأسية (Vertical Modules)     │
│  المرحلة 6: تفعيل معيار التخصيص لأي شركة (White-Label Multi-Tenant)    │
└────────────────────────────────────────────────────────────────────────┘
```


---

### 🟢 المرحلة 0: إعداد بيئة المشروع النظيف والحزم الأساسية
* **الهدف:** تجهيز البنية التحتية البرمجية المستقلة لمستودع `F:\Alsaada-Smart-Bot`.
* **المهام:**
  - إعداد ملفات التكوين الأساسية: `package.json`, `tsconfig.json`, `.gitignore`, `docker-compose.yml`.
  - تجهيز مساحات العمل (`pnpm-workspace.yaml`) لفصل الحزم عن الموديولات.
  - تجهيز بيئة الاختبارات السريعة عبر `Vitest`.
* **المخرجات:** مشروع نظيف قابل للتجميع والاختبار بنسبة 100%.

---

### 🟢 المرحلة 1: بناء الحزم التأسيسية (Foundation Packages)
* **الهدف:** نقل وتكييف الحزم المجرّبة والمستوحاة من Tempot.
* **المهام:**
  - `packages/national-id-engine`: محرك فحص واستخراج بيانات الرقم القومي المصري (14 رقماً).
  - `packages/regional-engine`: محرك توقيت القاهرة وعملة الجنيه المصري وتحويل الأرقام المشرقية.
  - `packages/ux-helpers`: مساعدات تجربة الاستخدام، والقاعدة الذهبية (`editOrSend`)، وتوكنات الأزرار المنتهية الصلاحية.
* **المخرجات:** حزم مستقلة تغطيها اختبارات وحدة بنسبة 100%.

---

### 🟢 المرحلة 2: بناء محرك قراءة الفواتير بالذكاء الاصطناعي (AI Vision Engine)
* **الهدف:** بناء المكون المتخصص في الرؤية الحاسوبية وقراءة المستندات (`packages/ai-vision-engine`).
* **المهام:**
  - دمج Vercel AI SDK مع نموذج Gemini 2.5 Flash Vision.
  - بناء مخطط استخراج الفواتير (`InvoiceExtractionSchema`) لاستخراج (المورد، المبلغ، التاريخ، البنود).
  - إضافة قواطع الأمان البرمجية (`cockatiel`) للتعامل مع انقطاع الشبكة وإعادة المحاولة.
  - بناء رادار مكافحة الفواتير المكررة ومطابقة الأسعار.
* **المخرجات:** دالة جاهزة تستقبل صورة الفاتورة وتُرجع كائناً برمجياً منظماً ودقيقاً بنسبة 100%.

---

### 🟢 المرحلة 3: بناء محرك التوليد الآلي لشيتات جوجل (Auto-Provisioner)
* **الهدف:** أداة لإنشاء وتجهيز الـ 66 شيت بضغطة زر واحدة لأي شركة.
* **المهام:**
  - بناء معجم المخططات القياسي (`Schema Registry`) للأعمدة والتبويبات والألوان والمعادلات.
  - كتابة محرك الاتصال بـ Google Sheets API عبر طلبات `batchUpdate` مجمعة.
  - إنشاء أمر `npm run system:provision` لاختبار إنشاء الشيتات على حساب تجريبي.
* **المخرجات:** القدرة على إنشاء بيئة شيتات متكاملة لأي شركة جديدة في أقل من 3 دقائق.

---

### 🟢 المرحلة 4: بناء المكونات المشتركة التفاعلية (Core UI Components)
* **الهدف:** المكونات الـ 8 المجهزة لاستدعائها المباشر داخل الموديولات.
* **المهام:**
  - `UniversalWorkerPicker`: محرك اختيار العمال الموحد مع البحث وترقيم الصفحات.
  - `UniversalAmountPicker`: محرك إدخال المبالغ النقدية والفئات السريعة وأمان التكرار.
  - `UniversalQuantityPicker`: محرك الكميات والوحدات.
  - `UniversalConfirmationCard`: بطاقة المراجعة وقفل التزامن الموزع (`Redis Mutex`).
  - `UniversalCompletionCard`: لوحة أزرار ما بعد الإنجاز (واتساب + تكرار العملية + العودة للقسم + القائمة الرئيسية).
* **المخرجات:** مكتبة واجهات جاهزة تختصر كود المحادثات بنسبة 80%.

---

### 🟢 المرحلة 5: نقل موديولات الأعمال الرأسية تباعاً (Vertical Modules)
* **الهدف:** نقل الموديولات خطوة بخطوة وتوثيقها واختبارها آلياً.
* **الترتيب المعتمد:**
  1. **موديول الكانتين والسجائر (`canteen`)** — كنموذج رائد (Pilot).
  2. **موديول السلف النقدية والمنح (`advances`)**.
  3. **موديول الإجازات والغياب (`leaves`)**.
  4. **موديول العهد النقدية ومصاريف الموقع (`custody`)** — مدمجاً به قارئ الفواتير بالـ AI.
  5. **موديول اللوجستيات والمحروقات (`logistics` & `fuels`)**.
  6. **موديول المخيم والعمليات الإدارية (`workforce`)**.
* **المخرجات:** منظومة موديولية كاملة معزولة وخالية من أي كود مكرر.

---

### 🟢 المرحلة 6: تفعيل معيار التخصيص لأي شركة (White-Label Multi-Tenant)
* **الهدف:** إتاحة تشغيل المنظومة لأي شركة بتغيير ملف إعداد واحد.
* **المهام:**
  - تجريد الثوابت وتفعيل ميزة `enabledModules`.
  - دعم تخصيص العملة والمواقع وفئات الأصناف وشعار الشركة.
