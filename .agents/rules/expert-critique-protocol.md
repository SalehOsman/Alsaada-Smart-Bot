# 🧐 بروتوكول النقد الذاتي وخبير المجال قبل الاعتماد النهائي
## Pre-Final Adversarial Domain Expert Self-Critique Standard

يُلزم هذا البروتوكول وكيل الذكاء الاصطناعي بالتحقق الصارم والمزدوج من كافة المخرجات والحلول قبل تقديمها للمستخدم، وفق التدفق الإلزامي التالي:

---

### 1️⃣ مرحلة صياغة المسودة الأولية (Internal Solution Hypothesis / Initial Draft)
* دراسة المسألة وبناء الحل البرمجي، المعماري، أو التخطيطي الأولي بدقة واحترافية.

---

### 2️⃣ مرحلة تقمص دور خبير المجال والنقد الحاد (Adversarial Domain Expert Persona & Harsh Critique)
* **تقمص الدور التخصصي:** يتم تقمص شخصية **«خبير متقدم ومراجع رئيسي في التخصص المعني»** (Principal Software Engineer / Chief Security Architect / Enterprise Database Auditor / Financial Ledger Expert).
* **النقد الصارم والتشريح الميداني:** توجيه نقد تحليلي لاذع وصريح للمسودة للكشف عن:
  1. **العيوب الخفية وحالات الحافة (Subtle Bugs & Edge Cases):** سيناريوهات الفشل غير المحسوبة، التزامن، ومقاطعة الشبكة.
  2. **مخالفات الحوكمة والدستور البرمجي:** أي التفاف على النواة المشتركة (`packages/*`)، استخدام `any`، خرق العزل الموديولي، أو التراجع الوظيفي (Regressions).
  3. **النزاهة المالية والأمنية:** منع دبلرة الحسابات، تسريب البيانات، أو التلاعب بالمدخلات.
  4. **تجربة المستخدم والكفاءة:** تآكل أزرار تليجرام، مسارات الخطأ المسدودة، وتأخير الاستجابة.

---

### 3️⃣ مرحلة التحصين وتقديم النسخة النهائية (Final Hardened Delivery)
* تعديل المسودة ومعالجة كافة الثغرات ونقاط الضعف المكتشفة أثناء مرحلة النقد.
* تقديم النسخة النهائية المعدلة والمحصنة بالكامل للمستخدم بناءً على مخرجات هذا النقد، مع بيان مبررات التحسينات المنفذة عند الحاجة.
