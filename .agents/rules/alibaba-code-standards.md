# 🛡️ دستور علي بابا لجودة وأمان الكود البرمجي — معايير السعادة سمارت بوت
## Alibaba Open Code Review (OCR) Permanent Engineering & Security Standards

تُطبق هذه القواعد تلقائياً وبشكل إلزامي على كافة أعمال التطوير، التعديل، والمراجعة البرمجية في مشروع `Alsaada-Smart-Bot`:

---

### 1️⃣ الخلو التام من الأخطاء اللغوية والإملائية (Zero Obvious Typos & Naming Precision)
* **دقة التسميات:** أسماء المتغيرات، الدوال، الكلاسات، والأنواع يجب أن تكون بالإنجليزية الصحيحة وبدلالة واضحة ومباشرة.
* **رسائل التسجيل والواجهات:** خلو رسائل التسجيل (`logger`) ونصوص واجهات المستخدم (`UI texts`) من أي أخطاء إملائية صريحة أو تشويه للنصوص العربية أو الإنجليزية.

---

### 2️⃣ الاستئصال الصارم للأكواد الميتة (Zero Dead Code Policy)
* **المتغيرات والواردات:** حظر تام لوجود واردات غير مستخدمة (`unused imports`) أو متغيرات محلية غير مستخدمة (`unused variables`).
* **الدوال والمسارات الميتة:** حذف أي كود لا يمكن الوصول إليه (`unreachable code`) أو توابع داخلية مهملة بعد إعادة الهيكلة.
* **الأكواد المعلقة:** يُحظر تماماً ترك كتل برمجية معلقة (`commented-out code blocks`) في مسارات الإنتاج.

---

### 3️⃣ الجودة المعمارية والتايب سكريبت الصارم (Strict Code Quality & TypeScript 5.9+)
* **حظر النوع `any`:** يُمنع استخدام `any` منعاً باتاً؛ يجب استخدام الأنواع الدقيقة (`Strict Types`)، الـ Generics المقيدة، أو `unknown` مع الـ Type Narrowing.
* **المساواة الصارمة:** استخدام `===` و `!==` حصراً، وحظر المقارنة الفضفاضة `==` و `!=`.
* **منع `var`:** استخدام `const` دائماً، و `let` فقط عند الحاجة لتغيير القيمة.
* **التحقق من القيم المنعدمة:** فحص إلزامي لقيم `null` و `undefined` باستخدام الـ Optional Chaining (`?.`) والـ Nullish Coalescing (`??`).
* **حظر التعابير الثلاثية المتداخلة:** يُمنع تماماً استخدام Nested Ternary Operators (`a ? b : c ? d : e`) لضمان المقروئية؛ استبدالها بـ `if/else` صريحة أو دوال فرعية.
* **منع التكرار (DRY):** استخراج المنطق المشترك في دوال ومكونات مستقلة والاعتماد الحتمي على حزم النواة `@alsaada/*`.

---

### 4️⃣ أفضل ممارسات React والواجهات (React & Next.js Standards)
* **قواعد الـ Hooks:** استدعاء الخطافات (`useState`, `useEffect`, ...) في المستوى الأعلى للمكون حصراً؛ يُحظر استدعاؤها داخل شروط أو حلقات.
* **منع التأثيرات الجانبية في العرض:** خلو مرحلة الـ Render من أي Side Effects أو تعديل مباشر للحالة (`setState` المباشر بدون أحداث أو Effects).
* **إدارة التبعيات:** اكتمال مصفوفة التبعيات (`dependency array`) في `useEffect` و `useCallback` و `useMemo` لتفادي الحلقات اللانهائية وتحديثات الحالة المتأخرة.

---

### 5️⃣ معالجة العمليات غير المتزامنة والتزامن (Robust Async & Concurrency)
* **المعالجة الإلزامية للأخطاء:** إحاطة استدعاءات الشبكة وقواعد البيانات والعمليات غير المتزامنة بـ `try/catch` مع تسجيل وتصعيد الأخطاء المهندسة.
* **`async/await` المعيارية:** تفضيل `async/await` الصريحة على سلاسل الـ `.then().catch()` المتداخلة.
* **التحكم في الحلقات والتوازي:**
  * العمليات المستقلة غير المتسلسلة يجب تجميعها عبر `Promise.all` أو `Promise.allSettled` مع ضبط التوازي (`concurrency limits`).
  * منع استدعاءات الـ await التسلسلية البطيئة داخل `for` loop إذا لم تكن العمليات تعتمد خطياً على بعضها.

---

### 6️⃣ الأمان الجنائي البرمجي والوقاية الميدانية (Code Security)
* **حظر دوال الحقن الديناميكي:** يُحظر تماماً استخدام `eval()` أو `new Function()` أو مناظراتها لتنفيذ نصوص ديناميكية.
* **منع تلوث النموذج الأولي (Prototype Pollution):** حظر دمج الكائنات غير المحمي عبر المفاتيح المحجوزة (`__proto__`, `constructor`, `prototype`).
* **الحماية من هجمات XSS:** تنقية كافة مدخلات المستخدم ومنع إدراج الـ HTML الخام غير المعقم (`dangerouslySetInnerHTML` بدون تعقيم صارم).
* **التطهير الصارم للأسرار (Zero Hardcoded Secrets):** يُحظر تضمين أي مفاتيح API، رموز سرية، أو بيانات اعتماد في الأكواد المصدرية؛ الاستيراد حصراً من بيئة التشغيل المشفرة (`env.ts`).

---

### 7️⃣ ميثاق السعادة سمارت بوت الميداني (Al-Saada Domain Rules)
* **حظر المزامنة اللحظية مع Google Sheets:** يُمنع أي استدعاء شبكي تزامني لـ Sheets API داخل معالجات الرسائل (`handlers`)؛ المزامنة حصراً عبر `TransactionalOutboxQueue`.
* **العزل الموديولي والتنقل الموضعي:** تعديلات الموديولات تظل معزولة داخل `modules/*`، والشاشات تُحدّث موضعياً (`renderWizardStep` / `editMessageText`) مع زر السابق المعياري.
* **المقاصة الثلاثية وسلامة القيود:** كافة العمليات المالية تلتزم بالـ Double-entry ونظام المقاصة المعتمد.

---

### 8️⃣ بروتوكول حلقة المراجعة والتصحيح الإلزامية قبل تسليم أي مهمة (Mandatory Review & Remediation Loop)
1. **حظر إعلان الإنجاز دون مراجعة الوكيل (`No Completion Without Review`):**
   - يُحظر تماماً على وكيل التطوير (Antigravity Primary Agent) إعلان انتهاء أي مهمة إنشاء أو تعديل برمجي أو عرض إنجازها للمستخدم كـ «مكتملة»، ما لم يقم باستدعاء وكيل المراجعة الدائم `code-reviewer` لفحص كافة الملفات المتأثرة والتغييرات في الـ git diff.
2. **عرض تقرير المراجعة المعياري للمستخدم:**
   - يلتزم الوكيل بعرض تقرير `code-reviewer` المجدول بشفافية تامة أمام المستخدم مبيناً تصنيف وخطورة كل ملاحظة.
3. **حلقة المعالجة وإعادة التدقيق (Remediation & Re-review Cycle):**
   - عند وجود أي ملاحظات هندسية أو أمنية:
     * يقوم وكيل التطوير بتطبيق التصحيحات والإصلاحات اللازمة في الكود.
     * يعيد وكيل التطوير استدعاء `code-reviewer` لفحص التصحيحات والتأكد من عدم توليد أي تراجعات (Zero Regression).
4. **بوابة الاعتماد والإغلاق النهائي (100% Clean Pass Gate):**
   - تستمر حلقة (التصحيح ⬅️ الفحص) حتى يُصدر وكيل المراجعة `code-reviewer` تقريره النهائي الحاسم:
     > **«✅ اجتاز الكود المراجع كافة معايير علي بابا وميثاق حوكمة السعادة بنجاح بنسبة 100% (Clean Pass) — الكود جاهز للاعتماد والدمج.»**
   - فقط عند هذه اللحظة، يحق لوكيل التطوير تقديم النتيجة النهائية للمستخدم واعتماد الـ Commit الموثق.
