# 📜 الوثيقة 28 — دستور إدارة الإصدارات الحية ومنهجية التحديثات الآمنة بنمط الأثر الصفري
## Al-Saada Enterprise Living Release & Safe Upgrade Sovereign Standard

> [!IMPORTANT]
> تمثل هذه الوثيقة **المعيار الهندسي والإجرائي الدائم (Permanent Engineering Standard)** لإدارة الإصدارات والتحديثات اللاحقة لمنظومة السعادة سمارت بوت.  
> تلتزم بها كافة أدوات ووكلاء الذكاء الاصطناعي (AI Agents) والمطورين البشريين دون أي استثناء.

---

### 1️⃣ فلسفة المنهجية وأطوار دورة حياة الإصدارات (Release Lifecycle Philosophy)
1. **النبذ التام للجمود الشكلي (Zero Frozen Versions):**
   - حظر تثبيت أو تجميد إصدار المنظومة عند رقم مصمت لا يعكس الواقع البرمجي؛ رقم الإصدار هو كائن حي يتصاعد ديناميكياً مع كل خطة عمل أو ميزة أو إصلاح.
2. **محطات الانتقال المعمارية الأربعة الصارمة (The 4 Lifecycle Milestones):**
   - **طور البناء والهجرة النشط (`Alpha Phase` — `v2.0.0-alpha.N`):**
     * الطور الحالي للمنظومة؛ يغطي بناء النواة وهجرة التدفقات الـ 126 من مشروع `F:\HR` وإرساء البنية التحتية.
     * يرتبط العداد $N$ مباشرة برقم خطة العمل المعتمدة المدمجة على `main` (مثلاً: بعد الخطة 83 نكون في `v2.0.0-alpha.83`، وتدشن الخطة 84 الإصدار `v2.0.0-alpha.84`).
   - **طور التجريب والتكامل الميداني (`Beta Phase` — `v2.0.0-beta.N`):**
     * يُدشن حصراً فور إعلان اكتمال ترحيل كافة التدفقات الـ 126 بنسبة 100% واعتماد سجل `docs/19`.
     * يُحظر في هذا الطور إضافة ميزات جديدة، ويُكرس لاختبارات المطابقة المحاسبية، وتكامل واجهات التليجرام والويب، وفحوصات الأداء والضغط.
   - **طور مرشح الإطلاق (`Release Candidate` — `v2.0.0-rc.N`):**
     * مرحلة التجميد البرمجي واختبارات الجاهزية القصوى والتدقيق الأمني النهائي (SAST + Secret Leakage + Forensic Audit).
   - **طور الإنتاج العام المستقر (`General Availability` — `v2.0.0`):**
     * التدشين الرسمي للمنظومة في بيئة الإنتاج السحابية المستقرة وإطلاق النسخة الرسمية للمستخدمين.

---

### 2️⃣ منظومة الأتمتة الذرية الصفرية (Zero-Manual-Touch Automation)
1. **حظر التعديلات اليدوية لبيانات الإصدار (Zero Manual Edits):**
   - يُحظر تماماً على أي مبرمج أو ذكاء اصطناعي فتح ملف `package.json` أو `CHANGELOG.md` أو ملفات التليمتري لتعديل الإصدار يدوياً.
   - تتم كافة التعديلات برمجياً وذرياً عبر محرك الإصدارات السيادي:
     ```bash
     pnpm release:bump
     ```
2. **آلية العمل الذاتي للمحرك (`tools/release/release-engine.ts`):**
   - يكتشف المحرك رقم الخطة واسمها تلقائياً من سياق فرع Git النشط (مثل `plan/84-safe-upgrade`).
   - يحدث رقم النسخة في `package.json` الرئيسي وحزم المنظومة.
   - يستخرج تفاصيل وأهداف الخطة ويولد قسماً منسقاً في `CHANGELOG.md`.
   - يحدث بيانات التليمتري الحية في `packages/telemetry/src/version.ts`.
   - يعيد احتساب بصمات SHA-256 ويختم `governance.lock.json` ذرياً لتفادي تعارض الـ Pre-commit Hooks.
3. **الوسم الآلي عند الدمج (Automated Sovereign Git Tagging):**
   - فور موافقة المستخدم بالصيغة الدستورية الحرفية: **«ادمج الفرع»**، يتكفل بروتوكول الدمج الصريح بقراءة النسخة من `package.json` وإطلاق وسم Git Tag المناسب آلياً وربطه برقم الخطة دون أي أمر يدوي.

---

### 3️⃣ حزمة أدوات التحديثات الآمنة المدمجة (Safe Upgrade Toolsuite)
تخضع كافة عمليات الترقية والتحديث للأدوات المدمجة في مجلد `tools/upgrade/`:

1. **رادار فحص الأثر متعدد المتجهات (`impact-scanner.ts`):**
   - يفحص استيرادات TypeScript، عقود أحداث EventBus، ونماذج Prisma عبر كافة الـ 126 تدفقاً والداشبورد.
   - يولد تقريراً مرئياً بدرجات الخطورة (Low, Medium, High, Critical) وحزم الاختبارات الاستهدافية.
   - يعمل بذاكرة كاش ذكية تقلص زمن الفحص إلى أقل من 1.5 ثانية.
2. **مدير الارتداد الفوري (< 60s) (`rollback-manager.ts`):**
   - يلتقط لقطة ذرية لـ Git Commit وملف `pnpm-lock.yaml` قبل أي تعديل.
   - يوفر أمر استرجاع فوري يعيد النظام لحالته النظيفة السابقة في أقل من دقيقة حال رصد أي خلل.
3. **مشغل بوابات الجودة الرباعية (`verify-upgrade.ts`):**
   - يختبر: فحص الأنواع الصارم ⬅️ اختبارات Vitest ⬅️ بوابات الحوكمة (Gate 21) ⬅️ أمان سلسلة التوريد.
4. **المعالج التفاعلي الشامل (`wizard.ts`):**
   - يدمج كافة المراحل السابقة خطوة بخطوة مع دعم راية المحاكاة `--dry-run`.

---

### 4️⃣ بوابة الحوكمة رقم 21 (Gate 21: Release & Changelog Parity)
- مدمجة إلزامياً في مسار `pnpm ci:simulate` عبر الأداة `tools/governance/verify-release-sync.ts`.
- **شروط الاجتياز:**
  1. تطابق تام بين حقل `version` في `package.json` وأحدث ترويسة في `CHANGELOG.md`.
  2. تطابق تام مع كائن النسخة المصدر في `packages/telemetry/src/version.ts`.
  3. قيد توثيق خطة العمل المنجزة وتاريخها بدقة.
- أي تباين يوقف عملية الـ Commit والدمج فوراً بـ `Exit 1`.

---

### 5️⃣ قواعد حماية النواة والغروب الصارم (Core Backward Compatibility & Sunset)
1. **حصر التصدير في الواجهة العامة (`Public API Barrel`):**
   - تُصدر كافة مكونات النواة في `packages/*` حصراً عبر `src/index.ts`. يُحظر على الموديولات والتدفقات استيراد ملفات داخلية مباشرة.
2. **حظر كسر التواقيع والالتزام بـ Deprecation:**
   - أي تعديل في توقيع دالة بالنواة يجب أن يكون إضافياً؛ الدوال المستبدلة تُنقل إلى `src/compat/` وتوسم بـ `@deprecated` مع تحديد إصدار الحذف النهائي.
3. **صمام الغروب الصارم (Sunset Enforcer):**
   - يُلزم كل وسم deprecation بتحديد إصدار الحذف: `@deprecated Remove in v2.0.0-alpha.X`. يتم فحص وتنظيف الدوال المتقادمة دورياً لمنع تراكم الأكواد الميتة.
