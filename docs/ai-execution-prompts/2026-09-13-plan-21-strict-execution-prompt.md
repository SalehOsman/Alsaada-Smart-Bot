## START OF PROMPT

أنت فريق تنفيذ هندسي متعدد الوكلاء يعمل داخل المشروع:

F:\Alsaada-Smart-Bot

مهمتك تنفيذ خطة العمل PLAN-21 تنفيذاً حرفياً وكاملاً، وفق التصميم المعتمد ودستور المشروع، دون توسيع النطاق أو تغيير أي سلوك خارج الخطة.

### أولاً: قاعدة التوقف قبل التنفيذ

لا تكتب أو تعدل أو تحذف أي كود قبل إتمام جميع الشروط التالية:

1. قراءة ملف AGENTS.md كاملاً من جذر المشروع.
2. قراءة أي AGENTS.md إضافي ينطبق على المسار المستهدف.
3. قراءة وثيقة التصميم التالية كاملة:

   docs/superpowers/specs/2026-09-13-unified-bot-dashboard-auth-rbac-parity-design.md

4. قراءة خطة PLAN-20 كاملة لفهم أعمال المصادقة والرصد السابقة وعدم كسرها:

   docs/work-plans/20-plan-release-recovery-dashboard-auth-and-professional-observability.md

5. العثور على خطة PLAN-21 المعتمدة وقراءتها كاملة:

   docs/work-plans/21-plan-unified-bot-dashboard-auth-rbac-and-functional-parity.md

6. التحقق أن PLAN-21:

   - موجودة فعلياً.
   - ليست مسودة غير معتمدة.
   - تحتوي على قائمة الملفات لكل مهمة.
   - تحتوي على اختبارات ومعايير قبول وأوامر تحقق.
   - لا تحتوي على TBD أو قرار غير محسوم.
   - تمت مراجعتها واعتمادها صراحة من المستخدم.

إذا كانت PLAN-21 غير موجودة أو غير معتمدة أو ناقصة، توقف فوراً ولا تنفذ أي تعديل. أرسل:

~~~text
STATUS: TASK_SUSPENDED_PLAN_NOT_READY
MISSING_OR_UNAPPROVED: <المسار أو البند>
EVIDENCE: <ما تم العثور عليه>
REQUIRED_ACTION: إنشاء أو استكمال أو اعتماد PLAN-21 قبل التنفيذ
~~~

هذا البرومبت ليس بديلاً عن PLAN-21، ولا يمنح صلاحية لبدء التنفيذ قبل اعتمادها.

### ثانياً: ترتيب مصادر الحقيقة

عند وجود اختلاف، طبق الترتيب التالي:

1. توجيه المستخدم الصريح الموثق.
2. وثيقة التصميم المعتمدة المذكورة أعلاه.

7. الكود الحالي كواقع يحتاج المراجعة، وليس مرجعاً أعلى من المتطلبات.

لا تغير سلوكاً موجوداً في F:\HR إلا إذا كان التغيير موثقاً كتوجيه مستخدم صريح.

### ثالثاً: قفل النطاق

التزم بالقواعد التالية دون استثناء:

1. لا تعدل ملفاً غير مذكور صراحة في مهمة PLAN-21 النشطة.
2. إذا احتجت ملفاً إضافياً، توقف واشرح السبب والأثر واطلب موافقة المستخدم قبل فتح نطاق التعديل.
3. لا تنفذ تنظيفاً عاماً أو Refactor جانبياً خارج المهمة.
4. لا تغير أسماء أو خطوات أو حسابات أو حالات أي وظيفة غير داخلة في المهمة.
5. لا تضف مكتبة أو خدمة خارجية أو SaaS أو حاوية جديدة ما لم تنص الخطة عليها صراحة.
6. لا تعدل packages المشتركة لحل مشكلة محلية إلا بعد Blast Radius Audit موثق وتشغيل اختبارات المستهلكين.
7. لا تعدل Schema أو Migration أو قواعد مالية دون مراجعة وكيل المالية والأمان ووكيل المعمارية وقواعد البيانات.
8. لا تحذف كوداً قديماً قبل:

   - إثبات وجود البديل.
   - البحث عن جميع المراجع.
   - تشغيل الاختبارات ذات الصلة.
   - توثيق ما سيحذف وسبب الحذف.

9. حافظ على تغييرات المستخدم الحالية في شجرة العمل، ولا تعكسها أو تدمجها في مهمتك دون سبب موثق.
10. يحظر استخدام:

   - git reset --hard
   - git checkout -- لمسح تغييرات
   - git clean
   - git commit --no-verify
   - تعطيل Hooks أو اختبارات أو بوابات حوكمة
   - تجاهل أخطاء TypeScript أو Lint أو Test

11. لا تنقل ملفات مؤقتة أو سكريبتات تجريبية إلى جذر المشروع.
12. كل تعديل ملفات يتم بعد القراءة الكاملة للملف وباستخدام apply_patch.

### رابعاً: بروتوكول منع الاجتهاد

1. ابحث في F:\HR والوثائق وعقود الوظائف والاختبارات.

لا تعتبر الصمت موافقة، ولا تكمل التنفيذ قبل الاستيضاح.

- WORKER
- SUPPLIER

#### 7.4 المستحقات التعاقدية

المستحقات السرية:

- الراتب الأساسي.
- الراتب الإضافي.
- البدلات الثابتة أو الدورية.
- الإجماليات أو الإحصائيات التي تكشف هذه القيم.

الصلاحيات:

- SUPER_ADMIN: عرض وتعديل واعتماد.
- GENERAL_ADMIN: عرض وتشغيل المسيرات والاعتماد دون تعديل القيم التعاقدية.
- FIELD_ADMIN: حجب كامل.
- WORKER وWORKER_SUPERVISOR: قسيمته الشخصية فقط.
- SUPPLIER وGUEST: حجب كامل.

الحجب يجب أن يحدث على الخادم وقبل الاستجابة، ويشمل API والبحث والتصفية والتصدير والطباعة والرسوم والسجلات.

#### 7.5 السلف والمسحوبات والعهد

FIELD_ADMIN داخل موقعه يستطيع:

- تسجيل السلف النقدية.
- تسجيل المسحوبات العينية.
- عرض سجلاتها.
- تسجيل العهد وتغذيتها وتشغيلها.
- تسجيل مصروفات العهد.
- تصفية العهد كاملة.

لا تكشف هذه الوظائف الراتب أو البدلات أو صافي المستحق.

#### 7.6 المكافآت والخصومات

FIELD_ADMIN:

- ينشئ طلباً فقط.
- يتابع حالته.
- يسحبه وهو PENDING وقبل بدء المراجعة.
- لا يعدله بعد الإرسال.
- لا يعتمد أو يرفض.
- لا ينشئ أثراً مالياً نهائياً.

GENERAL_ADMIN:

- عرض فقط.

SUPER_ADMIN:

- تعديل.
- اعتماد.
- رفض.
- إنشاء الأثر المالي النهائي.

لا ينشأ أثر مالي قبل APPROVED، ولا يحذف الطلب المسحوب؛ يتحول إلى WITHDRAWN.

#### 7.7 العامل المشرف

WORKER_SUPERVISOR:

- عامل يحتفظ بخدماته الذاتية.
- يملك تفويضاً أو أكثر على مستوى وظيفة دقيقة داخل موديول.
- لا يمنح الموديول كاملاً.
- كل تفويض يحدد PermissionKey والإجراء والموقع والمورد التشغيلي والمدة.
- النطاق هو موقع العامل المسجل فعلياً فقط.
- لا يملك all-sites.
- يتوقف التفويض عند النقل أو الإيقاف أو إنهاء الخدمة.
- تاريخ البداية إلزامي والنهاية اختيارية.
- أول تفويض يحوله إلى WORKER_SUPERVISOR.
- سحب آخر تفويض يعيده إلى WORKER.
- لا يدخل الداشبورد.

SUPER_ADMIN وGENERAL_ADMIN يمنحان ويسحبان التفويض.
FIELD_ADMIN يقدم طلباً فقط داخل موقعه.

يحظر تفويض الوظائف السيادية، ومنها إدارة الأدوار والرواتب وإعدادات النظام وخزنة الأخطاء والنسخ الاحتياطي والاعتمادات المالية النهائية.

#### 7.8 تطابق البوت والداشبورد

كل وظيفة بيانات أو أعمال في البوت يجب أن تمتلك واجهة داشبورد بنفس:

- الاسم العربي الرسمي.
- المدخلات.
- المخرجات.
- قواعد التحقق.
- الحسابات.
- الحالات.
- الصلاحيات.
- النطاق.
- حجب الحقول.
- أثر قاعدة البيانات وOutbox.

نفذ الوظيفة في البوت واختبرها أولاً، ثم نفذها في الداشبورد مباشرة.

حالات التتبع:

~~~text
LEGACY_AUDITED
BOT_IN_PROGRESS
BOT_VERIFIED
DASHBOARD_IN_PROGRESS
PARITY_VERIFIED
COMPLETE
~~~

يجوز تفعيل وظيفة البوت بعد BOT_VERIFIED. لا تسجل COMPLETE قبل PARITY_VERIFIED.

ابدأ بعد المصادقة والصلاحيات بإغلاق فجوة جميع وظائف البوت الحالية في الداشبورد قبل إنشاء وظائف جديدة.

#### 7.10 المصادقة من البوت فقط

احذف بعد استبدالها واختبار البديل:

- صفحة /login.
- Mini App Login.
- TWA Login.
- Telegram WebApp initData للمصادقة.
- OTP.
- إدخال التوكن اليدوي.
- /api/auth/telegram.
- /api/auth/twa.
- أمر /dashboard القديم خارج شاشة الإعدادات.
- الاختبارات والنصوص والمتغيرات والتوثيق غير المستخدم.

لا توجد صفحة دخول ويب بديلة.

فتح /admin بلا جلسة، أو انتهاء الرابط، أو تسجيل الخروج يعيد المستخدم إلى:

~~~text
https://t.me/<BOT_USERNAME>?start=dashboard_access
~~~

#### 7.11 الرابط المحلي والنفق

يجب أن يعملا في الوقت نفسه:

~~~env
DASHBOARD_LOCAL_URL=http://localhost:3002
DASHBOARD_TUNNEL_URL=https://your-tunnel-domain.example
~~~

- زران مستقلان داخل إعدادات البوت.
- رمز مستقل لكل زر.
- تعطل أحد المصدرين لا يعطل الآخر.
- يمنع أي Host أو Origin ثالث.
- لا تستخدم req.url أو Host Header غير موثوق لبناء redirect.
- اربط الرمز بهدف LOCAL أو TUNNEL.

#### 7.12 الجلسات

- رمز الدخول صالح خمس دقائق ولمرة واحدة.
- Claim ذري.
- جلسة خادمية ثماني ساعات.
- Session ID عشوائي مخزن Hash.
- HttpOnly وSameSite.
- Secure للنفق HTTPS.
- لا تخزن Tokens في localStorage أو sessionStorage.
- إبطال فوري عند تغير الدور أو الموقع أو حالة الحساب.

قبل انتهاء الجلسة بساعة:

- أرسل إشعار Telegram مرة واحدة.
- زر تمديد ثماني ساعات.
