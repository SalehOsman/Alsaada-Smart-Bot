# Comprehensive Remediation and Enforced Merge Gates Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans لتنفيذ الحزم بعد اعتماد نطاقها. هذه خطة رئيسية؛ تفصل كل حزمة إلى مهام تنفيذ واختبارات محددة قبل تعديل الكود.

**Goal:** إغلاق النتائج المثبتة R01–R17، وإثبات المطابقة الوظيفية، ومنع دمج أي تغيير يفشل في القواعد والاختبارات المطلوبة.

**Architecture:** Modular Monolith؛ طبقات كل تدفق داخل موديوله وفق الوثيقة 21، مع نواة مشتركة وPostgreSQL وTransactional Outbox. جهة التحقق والاعتماد مستقلة عن أداة كتابة الكود وصلاحياتها.

**Tech Stack:** TypeScript 5.9+، pnpm، grammY، Prisma/PostgreSQL، Redis، Vitest، Google Sheets، Docker، GitHub.

الأوامر المطلوبة بعد إصلاح تنفيذها:

تضاف فحوص التكامل وE2E والمطابقة والأداء والترحيل/الاستعادة والبوابات السلبية والإصدار. أي فحص مطلوب غير متاح يمنع القبول.

**قرار enforcement/merge-allow:** لا يسمح إلا بمطابقة source/base/merge/policy وموثوقية جهة النتائج ونجاح جميع المتطلبات واكتمال الجرد وصلاحية المراجعات وسلامة النطاق والقواعد. skipped أو neutral أو cancelled أو timeout أو نتيجة مفقودة لفحص مطلوب ليست نجاحاً.

الفاحص النهائي مطلوب من مصدر موثوق، ولا يحجب بـpaths-ignore. جهة التحقق تثبت عدم انطباق حالة من العقد، وليس بإعفاء يكتبه الوكيل. عند تعديل النواة أو القواعد أو الإعدادات تشغل جميع الموديولات.

الأدلة الآلية خارج checkout؛ التوثيق يحتوي النطاق وروابط النتائج. كل Commit جديد يعاد فحصه، بما فيه تعديل التقرير. لا يُطلب من تقرير أن يتضمن SHA لنفسه قبل وجوده، ولا تنسب نتائج قديمة إلى مصدر جديد.

المتحكم الموثوق لا يشغل كود PR بصلاحياته ولا يوقع stdout دون تحقق من المصدر والجرد. تضبط CI بحسب [إرشادات أمان GitHub Actions](https://docs.github.com/en/actions/reference/security/secure-use)، مع أقل الصلاحيات وعزل الأسرار عن الكود غير الموثوق.
