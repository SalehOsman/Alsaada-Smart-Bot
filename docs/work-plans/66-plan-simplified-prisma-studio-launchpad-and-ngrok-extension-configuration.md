# خطة عمل رقم 66 (النسخة النهائية المعتمدة بعد النقد الهندسي): قمرة إطلاق استوديو بريزما السيادية وضبط نفق Ngrok ومعالجة خطأ 3004

## 📌 خلفية الخطة وسياقها المعماري (Architectural Context)
بناءً على النقد الهندسي الصارم (`/open-code-review`) من منظور **خبير شبكات Ngrok، وبنية Prisma Studio الداخلية، والأمان السيبراني Zero-Trust**:
1. **تشريح أزمة شاشة بريزما (الصور 2 و 3):**
   - استوديو بريزما مبني كتطبيق SPA مستقل عبر Vite/React، ويعتمد على حزم جافاسكريبت ديناميكية، وعمال ويب (WebWorkers)، ومسارات نسبية صلبة، وقنوات فحص حالة مستمرة.
   - محاولة تمرير هذه الحزم عبر مسار بروكسي داخلي في Next.js App Router (`/api/admin/studio/proxy/[[...path]]`) وإعادة كتابتها برمجياً عبر الـ Regex كانت فكرة ترقيعية فاشلة أدت لتعقيد دوري مرتفع (Cyclomatic Complexity 23 بحسب تقرير Alibaba OCR) وتسببت في شاشة بيضاء/سوداء وكسر مسارات الـ Vite Chunks.
   - **القرار الحاسم:** استئصال البروكسي الداخلي بالكامل، والاعتماد على نموذج **قمرة الإطلاق السيادية (Sovereign Launchpad)** لفتح الاستوديو في لسان مستقل بكامل ميزاته الأصلية.
2. **تشريح أزمة نفق Ngrok وخطأ ERR_NGROK_3004 (الصورة 1):**
   - خطأ `ERR_NGROK_3004` في Ngrok يعني حرفياً: `Tunnel points to an address that is not listening for connections or upstream connection refused`.
   - في إضافة Docker Desktop Ngrok Extension، حدث هذا بسبب أحد ثلاثة أسباب شبكية:
     * **تضارب المنفذ الداخلي والخارجي:** حاوية الداشبورد تستمع داخلياً على المنفذ `3002`، بينما حاوية البوت تستمع داخلياً على `3000` ومكشوفة للمضيف على `3001`. إذا وُجه النفق لمنفذ خاطئ أو إلى `127.0.0.1` داخل شبكة الحاوية الافتراضية، يُرفض الاتصال فوراً.
     * **تضارب البروتوكول:** توجيه النفق ببروتوكول `HTTPS upstream` بدلاً من `HTTP upstream` الواضح لخادم Next.js الداخلي.
     * **تضارب مسار المصادقة:** محاولة فتح الرابط عبر متصفح طرفي دون ترويسة `ngrok-skip-browser-warning`.
3. **التحذير الأمني الحرج لكشف بريزما عبر الإنترنت (Prisma Zero-Authentication Invariant):**
   - **استوديو بريزما لا يملك أي نظام تسجيل دخول أو مصادقة على الإطلاق (Zero Native Auth).**
   - تشغيل الاستوديو محلياً على `http://localhost:5555` آمن 100% لأنه محمي داخل شبكة المضيف المحلي (Loopback).
   - فتح بريزما على نفق عام بدون حماية يمثل ثغرة أمنية كارثية تسمح لأي شخص بالعبث المباشر بجداول قاعدة البيانات وحذف القيود.
   - لذلك، يجب أن توفر قمرة الإطلاق تحذيراً أمنياً صارماً، مع توفير خيار إدخال رابط نفق محمي أو رابط نفق مخصص مع حفظه محلياً في المتصفح (`localStorage`).
