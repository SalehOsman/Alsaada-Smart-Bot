## 🏛️ قرارات التصميم والمعمارية المعتمدة (Architectural Consensus)

1. **فصل الإجراء البشري عن الكود التقني في عمودين مستقلين (Dual-Column Trigger Resolution):**
   - **عمود الإجراء أو الزر المنفذ (الوصف البشري):** يعرض اسماً عربياً فائق الوضوح يعكس بدقة اسم الشاشة أو الزر في واجهة البوت مصحوباً بأيقونة تعبيرية دالة (مثال: `📸 تحليل بطاقة بالذكاء الاصطناعي (OCR)`، `👤 استعراض بطاقة العامل 360`، `📁 أرشيف مستندات العامل`، `🏠 القائمة الرئيسية`).
   - **عمود الرمز البرمجي للتليجرام (Technical Trigger):** يعرض الرمز البرمجي الدقيق (`photo:upload`، `cb:action:worker:view:...`) بخط مونو مصغر لخدمة المطورين والدعم التقني.

2. **شاشة أحدث 10 عمليات تم رصدها في المنظومة (Latest 10 Recorded Operations):**
   - إضافة جدول جديد موازٍ لجدول "أبطأ 5 عمليات"، يعرض العمليات العشر الأخيرة المنفذة لحظياً في البوت بترتيب زمني عكسي (`orderBy: { timestamp: 'desc' }, take: 10`).
   - يتضمن الجدول: الترتيب، الإجراء البشري، الكود البرمجي، زمن الاستجابة الكامل مع وسام ملون (أخضر < 50ms، برتقالي 50-250ms، أحمر > 250ms)، معرف المستخدم، والتوقيت الميداني الدقيق.

3. **تفكيك زمن الاستجابة (Latency Decomposition Breakdown):**
   - إظهار تفكيك زمن الاستجابة لكل عملية في الجداول وبطاقات الإحصاء:
     * **زمن المعالجة الداخلية للخادم (`Internal Server Processing`):** سرعة كود البوت واستعلامات قاعدة البيانات (المعيار الذهبي < 15ms).
     * **زمن شبكة تليجرام الخارجية (`Telegram Network Round-Trip`):** زمن الإرسال والاستقبال عبر خوادم تليجرام الدولية.
   - هذا التفكيك يوضح للإدارة فوراً إن كان أي تأخير سببه خادم المنظومة الداخلي أم شبكة الاتصال الخارجية لتيليجرام.

4. **مركز تحسين وتشخيص السرعة التفاعلي (Interactive Speed Optimization & Diagnostics):**
   - **بطاقة التشخيص الذكي اللحظي (Smart Advisory Card):** قراءة حية لآخر 500 عملية، وتقديم تشخيص فوري للإدارة يشرح سبب بطء العمليات المرصودة (مثل توضيح أن بطء `photo:upload` ناتج عن زمن استدعاء نموذج Google Gemini 1.5/2.0 لتحليل مستندات وصور الهوية، بينما كود البوت وقاعدة البيانات يستجيبان في أجزاء من الثانية).
   - **أزرار الإدارة والتحسين السريع:**
     * **زر فحص زمن الاستجابة اللحظي (Live Ping Benchmark):** قياس استجابة قاعدة البيانات PostgreSQL وكاش Redis فوراً من الواجهة.
     * **زر تنظيف وأرشفة السجلات القديمة (Purge Old Logs):** للحفاظ على خفة قاعدة البيانات وسرعة استعلامات جدول `bot_performance_logs`.
