### 2️⃣ ميثاق المصادقة والأمان: الربط المشفر عبر واتساب الرقم الرسمي للعامل (Cryptographic WhatsApp Linking)

#### 🛡️ تحليل التهديد الأمني (Threat Model):
لو تم الاعتماد على مطابقة البيانات وحدها (الرقم القومي أو الهاتف أو كود العامل) بمجرد موافقة السوبر أدمن، يستطيع أي شخص يعرف هذه البيانات العامة للعامل تقديم طلب من حسابه الشخصي في تليجرام، وإذا وافق السوبر أدمن يتم اختطاف حساب العامل والاطلاع على راتبه وسلفه!

#### 🔐 القرارات المعمارية المعتمدة للربط المشفر:
1. **مدة صلاحية الرمز الرقمي (TTL):** صلاحية الرابط المشفر هي **24 ساعة كاملة (86,400 ثانية)** لتناسب ظروف الميدان وضعف التغطية في مواقع العمل النائية.
2. **الربط التشفيري الصارم بمعرف التليجرام (Strict Cryptographic Telegram ID Binding):**
   - يُربط التوكن تشفيرياً بالمعرف الرقمي لتليجرام الخاص بمقدم الطلب (`applicantTelegramId = ctx.from.id`).
   - عندما يُفتح الرابط في تليجرام، يتحقق البوت فوراً من أن `ctx.from.id === tokenPayload.applicantTelegramId`.
   - إذا فتح الرابط أي شخص آخر أو لم يتطابق المعرف الرقمي، يتم رفض العملية فورياً وحظرها (`Hard Rejection`).
3. **الإرسال الحصري لواتساب الرقم الرسمي للعامل (`Worker.phone`):**
   - يُرسل الرابط حصراً إلى رقم الواتساب الرسمي المسجل للعامل في عقد العمل وقاعدة بيانات الشركة.
4. **استخدام لمرة واحدة وإبطال فوري (`Single-Use & Invalidation`):**
   - الرمز الرقمي صالح للاستخدام مرة واحدة فقط (`Single-Use`). فور استهلاكه بنجاح أو عند توليد رمز جديد للعامل، يتم إبطال الرمز القديم تلقائياً.
5. **خطوات التدفق:**
   - **أولاً:** يقدم الزائر طلب الانضمام عبر تدفق `01.7-guest-join-and-linking` (بالأمر `/apply` أو الزر المخصص).
   - **ثانياً:** يظهر للسوبر أدمن إشعار الطلب مع معرف تليجرام مقدم الطلب ورقم الواتساب الرسمي للعامل.
   - **ثالثاً:** يضغط السوبر أدمن زر توليد الرابط والإرسال لواتساب العامل الرسمي:
     `https://t.me/AlsaadaSmartBot?start=link_CODE_APPLICANTID_EXPIRY_SIGNATURE`
   - **رابعاً:** يفتح العامل الرابط من هاتفه عبر تليجرام، يتحقق البوت من التوقيع وسلامة المعرف الرقمي وعدم انتهاء الـ 24 ساعة، ويتم الربط وتفعيل الحساب كعامل فوراً وتحديث الأوامر والقائمة.

### 3️⃣ ميثاق إنهاء خدمة العامل والتحول اللحظي لزائر (Worker Offboarding Demotion)

في تدفق `01.8-worker-offboarding` بموديول شؤون العاملين، فور اعتماد سند المخالصة وإنهاء الخدمة:
1. **فصل حساب التليجرام:** إلغاء ارتباط سجل العامل بحساب التليجرام (`Worker.telegramId = null`, `Worker.status = 'TERMINATED'`).
2. **الهبوط التلقائي لدور زائر:** تعديل دور المستخدم في قاعدة البيانات إلى: `User.role = 'GUEST'`.
3. **تصفير الصلاحيات والمواقع والعهد:** ضبط `User.workerId = null` و `User.assignedSiteId = null`.
4. **إبطال الكاش اللحظي فورياً:** تفريغ كاش الذاكرة L1 وكاش Redis للمستخدم (`invalidateUserCache(telegramId)`).
5. **المزامنة اللحظية للأوامر الجانبية:** تقليص أوامر التليجرام فورياً لتقتصر على أوامر الزائر الأربعة (`/start`, `/cancel`, `/apply`, `/status`).
6. **حجب الأقسام التشغيلية:** عند فتح البوت، يُعامل المستخدم **كزائر 100%**؛ تختفي أمامه الأقسام الخمسة وتظهر شاشة الزائر النظيفة.

### 4️⃣ مصفوفة الأوامر متعددة الأشكال والتوجيه الديناميكي (Polymorphic Commands Matrix)

بناء موجه مركزي (`command-polymorphic.router.ts`) يوزع الأوامر ديناميكياً بناءً على الدور الفعلي (`effectiveRole`):
- **/profile:**
  * المدير العام والمشرف الميداني -> عرض الملف الشخصي الإداري.
  * العامل -> استعراض بطاقة العامل الشاملة وبوابة الملف الشخصي.
  * الزائر -> بطاقة المعرف الرقمي وحالة الحساب.
- **/leave:**
  * العامل -> فتح معالج طلب الإجازة.
  * باقي الأدوار -> تنبيه بأن طلب الإجازات مخصص للعاملين فقط.
- **/advance:**
  * العامل -> فتح معالج طلب السلفة.
  * المشرف / المدير -> إدارة ومراجعة طلبات السلف.
- **/help:**
  * دليل الاستخدام والتعليمات المخصص لكل دور.
- **/apply:**
  * الزائر -> بدء معالج تقديم طلب انضمام وربط الحساب.
  * المسجلون مسبقاً -> إفادة بأن الحساب مسجل ومفعل بالفعل.
- **/status:**
  * الزائر -> فحص حالة طلب الانضمام المعلق.
  * العامل -> عرض الحالة الوظيفية.

### 5️⃣ قصر أوامر الزائر وحجب الأقسام التشغيلية (Strict Guest Scoping)

- أوامر الزائر محصورة في 4 أوامر حصراً: `/start`, `/cancel`, `/apply`, `/status`.
- إخفاء الأقسام الخمسة (الموارد البشرية، المالية، التشغيل، التعيينات، الحوكمة) تماماً عن الزائر.
- إظهار أزرار الزائر المعتمدة:
  1. `[ 📝 تقديم طلب انضمام وربط حساب ]` -> `wizard:guest_join:start`
  2. `[ 🔍 الاستعلام عن حالة طلب الانضمام ]` -> `action:guest_join:status`
  3. `[ ❓ دليل الاستخدام واللوائح ]` -> `menu:guest:guide`
  4. `[ 🆔 بطاقة معرف حسابي ]` -> `action:guest:identity`

### 6️⃣ حظر مركز الإعدادات بالمحاكاة وتعديل واجهة المشرف (Settings & Field Admin Hardening)

1. **حظر مركز الإعدادات في وضع المحاكاة (Ghost Mode Masking):**
   - مركز الإعدادات والتحكم السيادي مخصص حصراً للمدير العام الحقيقي عندما يكون `effectiveRole === 'SUPER_ADMIN'` وبدون محاكاة (`!ctx.isImpersonating`).
   - عند المحاكاة، يُحجب مركز الإعدادات تماماً لمنع أي تسريب إداري.
2. **تعديل اسم زر المشرف:**
   - تعديل زر المشرف في لوحة الرد السفلية إلى `👤 ملفي الشخصي` (بدلاً من `👤 ملفي وإعداداتي`) لتوحيد الواجهات وحظر الإيحاء بوجود إعدادات.
3. **تحديد موقع المشرف في Ghost Mode:**
   - عند محاكاة المشرف الميداني، ترجيح المواقع النشطة التي تحوي عمالة فعلية (`workers: { some: { isDeleted: false } }`) لضمان عدم ظهور 0 عمال.

### 7️⃣ تفكيك بوابة العامل إلى 5 بوابات متخصصة (Worker Portal Sub-Hubs)

تقسيم واجهة العامل إلى 5 بوابات تخصصية رئيسية لتسهيل الوصول والتنقل:
1. `menu:worker_sub:profile`: 👤 **ملفي وبياناتي الشخصية** (استعراض الملف، طلب تعديل البيانات، البطاقة الرقمية).
2. `menu:worker_sub:finance`: 💰 **المستحقات والماليات** (كشف الحساب والمسحوبات، مفردات الراتب، طلب سلفة).
3. `menu:worker_sub:attendance`: ⏱️ **الدوام والحضور والإجازات** (رصيد الإجازات، تقديم طلب إجازة، نظام الوردية).
4. `menu:worker_sub:custody`: 🦺 **العهد ومهمات الوقاية** (عهد PPE، طلب استبدال مهمات).
5. `menu:worker_sub:support`: 💬 **الدعم والشكاوى واللوائح** (تقديم تظلم، اللوائح، جهات الاتصال).
