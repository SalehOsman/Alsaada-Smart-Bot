## 🔬 0. التشخيص الجنائي للواقع الفيزيائي (Forensic Root Cause Analysis)

كشفت التجربة اليدوية للمالك من خلال تليجرام عن حقيقتين فيزيائيتين:
1. **الصورة الثانية (سجل النسخ):** نجاح تام بنسبة 100%؛ حيث يقرأ البوت الخزينة الحقيقية (`/app/backups`) ويعرض اللقطات الست بأحجامها الفعلية الدقيقة (~7.2 MB) وبصماتها السليمة `🟢 سليم`.
2. **الصورة الأولى (زر نسخ الآن):** عند الضغط على `📦 نسخ الآن`، أعاد البوت لقطة وهمية بحجم **10.00 MB** وبحالة `staged`؛ والسبب الجذري الدفين هو:
   - دالة `executeBackupNow()` في `flow.service.ts` تحاول استيراد ملف `tools/backup/backup-manager.js`.
   - مجلد `tools/` غير منسوخ داخل حاوية إنتاج البوت (`docker/Dockerfile`).
   - ملف `backup-manager.ts` مكتوب بلغة TypeScript وغير مجمع إلى JavaScript.
   - عدم وجود أدوات `pg_dump` و `pg_restore` (حزمة `postgresql-client`) داخل حاوية تشغيل البوت `alpine`.

### الركن الثالث (Pillar 3): تدفق الاستعادة الحية المباشرة في تليجرام (Live Restoration UX Flow)

```mermaid
stateDiagram-v2
    [*] --> BackupList: الضغط على "📋 سجل النسخ"
    BackupList --> SnapshotDetail: اختيار لقطة (bck:sel:ID)
    
    state SnapshotDetail {
        [*] --> ViewMetadata: عرض الحجم والتاريخ والبصمة
        ViewMetadata --> ConfirmCard: الضغط على "♻️ استعادة حية" (bck:rst:ID)
        ViewMetadata --> BackupList: الضغط على "🔙 رجوع" (bck:list)
    }

    state ConfirmCard {
        [*] --> WarningScreen: تحذير أمني وبيان العواقب
        WarningScreen --> ExecutingRestore: الضغط على "✅ نعم، استعد الآن" (bck:cfr:ID)
        WarningScreen --> SnapshotDetail: الضغط على "❌ تراجع" (bck:sel:ID)
    }

    state ExecutingRestore {
        [*] --> SafetySnapshot: أخذ لقطة أمان مسبقة تلقائياً
        SafetySnapshot --> DBRestore: تفريغ واستعادة قاعدة البيانات
        DBRestore --> FinancialGate: التحقق المالي والحسابي بعد الاستعادة
        FinancialGate --> RestoreSuccess: عرض بطاقة النجاح وزمن الـ RTO
    }

    RestoreSuccess --> BackupList: الضغط على "📋 السجل"
```

1. **بطاقة تفاصيل اللقطة (Snapshot Detail Card):**
   - تعرض تاريخ الإنشاء، الحجم الحقيقي، معرف النسخة، وسلامة بصمة SHA-256.
   - الأزرار:
     * `♻️ استعادة حية` (`bck:rst:<ID>`)
     * `☁️ فتح في درايف` (رابط مباشر لمجلد Google Drive)
     * `🔙 رجوع للسجل` (`bck:list`)
2. **شاشة التحذير والتأكيد التفاعلي (Confirmation Card):**
   - رسالة واضحة: *"⚠️ تنبيه: ستتم استعادة قاعدة البيانات واستبدال الحالة الحالية باللقطة المحددة. سيتم أخذ لقطة أمان مسبقة تلقائياً."*
   - زر التأكيد: **`✅ نعم، استعد الآن`** (`bck:cfr:<ID>`).
   - زر الإلغاء: **`❌ تراجع وإلغاء`** (`bck:sel:<ID>`).
3. **التنفيذ غير المتزامن مع تحديث موضعي لحظي (<500ms):**
   - تحديث الرسالة فوراً: *"⏳ جاري أخذ لقطة أمان واستعادة قاعدة البيانات..."*.
   - تنفيذ الاستعادة الحقيقية في قاعدة بيانات `alsaada_db`.
   - فحص القيود المحاسبية بعد الاستعادة.
   - تحديث الرسالة بتقرير النجاح والـ RTO ورقم لقطة الأمان المسبقة.
